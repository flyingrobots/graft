# v0.13.0

## Summary

v0.13.0 removes the setup ceremony from the first daemon-backed repository
call and moves every production WARP working graph out of the source Git
repository.

An agent can call a routed tool such as `safe_read` with `cwd` set anywhere
inside a Git worktree. Graft resolves and opens the canonical containing
worktree with the default profile, performs the call, and leaves the session's
active binding unchanged. Its WARP graph lives in a private bare sidecar keyed
by repository, worktree, and actor identity.

## What Changed

- Routed daemon repository tools automatically open an explicit `cwd` on the
  first call. `workspace_open` remains available for activation and capability
  configuration.
- WARP persistence now defaults to
  `~/.graft/graphs/<project>/<worktree>/<actor>/warp.git`. Readable directory
  names include deterministic identity suffixes.
- Linked worktrees and independent MCP sessions receive different graph stores
  and cannot reuse one another's in-memory graph handles.
- The public `CreateGraftServerOptions` and `StartDaemonServerOptions` types
  gain the optional additive `graphRoot` field. Blank, symlink-aliased, and
  source-overlapping roots fail before storage mutation.
- First-time sidecar creation is atomic across processes, and exact concurrent
  opens coalesce within a process.
- Every supported Vitest path uses a digest-pinned, copy-in Docker image. The
  image excludes the live checkout's Git metadata, strips any copied Git
  remotes or worktree pointers, pins the Alpine Git package revision, disables
  network access after project-source copy, uses a unique image reference per
  invocation, and runs without network or host mounts.

## Why It Matters

The first useful daemon call no longer fails merely because the caller omitted
a separate registration step. At the same time, structural indexing can no
longer add WARP refs or objects to the repository an agent is inspecting.
Repository, worktree, and actor identity now select both the persistent store
and the in-memory handle, which prevents agents in parallel worktrees or
sessions from reading the wrong working graph.

## Breaking Changes

No package entry point was removed or renamed. The optional `graphRoot` field is
additive.

This release intentionally changes persistence behavior: existing WARP refs in
a source repository are not used by new production sessions, and one working
graph is no longer shared across worktrees or independent actors. Graft leaves
legacy `refs/warp/*` untouched; it does not import, merge, or delete them.

## Migration

- Daemon clients may replace a mandatory `workspace_open` prelude with an
  explicit `cwd` on the first routed repository-tool call.
- Keep `workspace_open` when the client wants to activate a workspace or enable
  non-default capabilities such as `runCapture`.
- Hosts that need a non-default sidecar location may set `graphRoot`; it must be
  a non-symlinked location disjoint from the source worktree and common Git
  directory. Most users need no configuration.
- No automatic data migration is required or performed. If legacy WARP history
  matters, retain the source refs until an explicit migration policy exists.

## Known Limits

- Sidecar retention and pruning are not automated yet.
- Actor sidecars isolate working graph state; they do not merge actor histories
  or prove ownership of overlapping live-file edits.
- Separate one-shot CLI processes in one worktree intentionally share the
  stable CLI operator lane. Use independent MCP sessions for parallel-agent
  history isolation.
- An explicit routed `cwd` is opening intent within Graft's same-user local
  threat model. Graft does not provide a multi-user authorization boundary.
