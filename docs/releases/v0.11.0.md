# v0.11.0

## Summary

v0.11.0 is a projection broker release. It publishes the Graft APIs needed for
dirty-buffer Edict projection, reusable language-provider routing,
profile-aware authority context, the Wesley SDL provider seam, and opaque Echo
receipt projection preservation.

This release does not execute Echo, admit Jim artifacts, canonicalize Echo
receipt bytes, settle consequences, or make Graft interpret Wesley extension
semantics. Graft routes projection requests and preserves support context;
language and runtime authorities keep their own meanings.

## What Changed

- `.edict` buffers can be projected through an Edict CLI provider using dirty
  source text over stdin JSONL. The result exposes syntax, diagnostics, Core,
  Target IR, and digest-oriented projection slots with explicit slot states.
- Projection providers can be registered through a reusable registry and
  resolved by language id or extension. The older direct `edictProjector`
  option remains supported.
- Projection bundles can carry authority context, including profile id,
  provider id, language id, profile digest, routing digest, and extension
  identities.
- Projection profiles can be resolved in memory with deterministic
  profile/routing digests and structured failures for unknown profiles,
  ambiguous matches, no-provider cases, and malformed profile data.
- `.graphql` and `.graphqls` buffers can route to a profile-aware Wesley SDL
  provider seam. Graft passes the resolved authority context to Wesley but does
  not interpret SDL directives or domain extension semantics.
- XML/SVG projection authority failures now remain explicit instead of falling
  back to native projection lanes after an authority-resolution failure.
- Edict projection bundles can preserve opaque `echoReceipt` slots for future
  Echo obstruction receipt display. Graft rejects top-level `receiptDigest`
  fields until canonical Echo receipt bytes exist.

## Migration

No migration is required for existing CLI, MCP, or API users.

Hosts that want the new projection routing model should:

1. Keep using direct provider options where that is already sufficient.
2. Use `createProjectionProviderRegistry(...)` when multiple languages or
   synthetic buffers need provider routing.
3. Add `createProjectionProfileResolver(...)` when a buffer needs explicit
   profile context, extension identity, or profile/routing digest visibility.
4. Treat receipt projection payloads as opaque display data until a later Echo
   release freezes canonical receipt bytes.

## Known Limits

- No `graft.projections.toml` project-file discovery is implemented in this
  release.
- The Wesley provider is a seam for hosts to supply a Wesley authority; this
  release does not ship a Wesley CLI/WASM adapter.
- Graft does not execute Echo, admit Jim artifacts, or claim settlement
  authority.
- Echo receipt digests are intentionally not accepted because canonical Echo
  receipt bytes are not frozen yet.
